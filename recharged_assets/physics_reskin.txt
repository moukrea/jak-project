# Grecharged-secondary-motion — WEIGHT TRANSFER onto physics joints.
#
# Applied by .autoport/physics_c7_reskin.py, between prep_hd_actor_glb.py and `hd_merc_swap add`
# in scripts/shell/build_enhanced_models.sh.  It changes SKIN WEIGHTS ONLY — same joints, same
# joint positions, same triangles, same textures.
#
# WHY THIS FILE EXISTS.  A physics chain can only move the screen through the vertices its joint
# is weighted to.  The cycle-7 audit (.autoport/physics_c7_skinmap.py, report skinmap.txt) found
# joints that the donor's artist painted DECORATIVELY: present in the rig, weighted at a few
# percent, dominated everywhere by an animated body bone.  The solver moves them correctly and
# almost nothing moves on screen — which is exactly the owner's "ca bouge un poil" followed by
# "aucune difference" after two cycles of tuning the solver.
#
# KEYS
#   transfer <joint> from=<a,b,...>  the joint to strengthen, and the bones to take the weight from
#   cap=C     weight the STRONGEST vertex of the patch ends up carrying (1.0 = fully detached from
#             the body; never use 1.0 on a body part — a breast is attached to a chest, and the
#             blend at the base is what keeps it attached)
#   shape=S   exponent on the artist's own normalised profile.  1.0 = pure rescale (keeps the
#             artist's falloff exactly).  <1 widens the shoulder so more of the patch moves
#             TOGETHER as a volume instead of only the centre — that is the cure for "seuls les
#             bouts bougent" / "flasque".
#   grow=U    optional: first extend the patch to any vertex within U game units of it, for a
#             painted patch too small to be a volume at all.  0 = keep the artist's support.
#
# The artist's spatial profile is never replaced, only rescaled: the vertex he weighted most stays
# the one weighted most.
#

#
# Defaut PRIORITE 1 de l'owner (`hair-skinning`, 13e passe) et defaut `hair-nape` :
#   « la physique ne s'applique pas a toute la geometrie de ces deux meches mais a seulement une

#
# CE QUI A CACHE CE DEFAUT PENDANT SIX PASSES — une mesure qui comptait un os IMMOBILE comme moteur.
# `ROOM-SKINCOV` calcule la part du poids portee par « les joints simules de la chaine », maillon 0
# COMPRIS. Or `rootlock=1` veut dire que le maillon 0 chevauche son os porteur RIGIDEMENT, et la
# course le publie elle-meme : `ROOM-GRADIENT ... link0=0.0000` sur les CINQ pilotages. Un sommet
# pese sur ce joint est donc aussi immobile que s'il etait pese sur `head` — mais il etait compte
# comme pilote. L'ecart mesure (`.autoport/probe_skin_profile.py`, mesh LIVRE) :
#
#     chaine      cov publie   part reellement MOBILE      pointe (dernier decile)
#     rbang         0.9703            0.4353                     1.00
#     lbang         0.9791            0.4734                     1.00
#     backhair      0.7390            0.3339                     0.46   <-- la pointe est SOUDEE
#     earL          0.8432            0.5183                     0.71   <-- idem
#     earR          0.8438            0.5210                     0.71   <-- idem
#
# LA REGLE, ET ELLE SE LIMITE D'ELLE-MEME : une chaine ancree a la racine DOIT avoir un profil qui
# MONTE vers 1.0 a la pointe (SPEC 2 : « le mouvement croit vers la pointe, et c'est SUR LA POINTE
# qu'on juge s'il y a du mouvement »). `lbang`/`rbang` finissent a 1.00 — leur profil bas au depart
# est l'ANCRAGE, il est correct, et on n'y touche pas. `backhair` plafonne a 0.48 sur TOUTE sa
# longueur et `earL/R` a 0.71 : ce ne sont pas des ancrages, ce sont des pointes qui ne peuvent pas
# bouger quel que soit le reglage du solveur. Seules ces deux-la sont traitees.
#
# LES TROIS QUESTIONS DE LA SPEC 7, repondues avant d'ecrire la mesure qui juge ce bloc :
#   NATURE : un PROFIL le long de la meche, pas un scalaire — deux etats opposes (ancrage sain vs
#            pointe soudee) rendent le meme `cov`, et c'est ce qui a laisse passer le defaut.
#   REPERE : abscisse curviligne de la polyligne des joints de la chaine, pose de bind, racine=0.
#   ABSENT : le profil monte vers ~1.0 au dernier decile. `lbang`/`rbang` le font DEJA et servent
#            de temoin sain interne — si ce bloc les degradait, il serait faux.
#
# `shape=1.0` EST UN CHOIX CONTRAINT, PAS UN REGLAGE : c'est le rescale PUR, qui multiplie tout le
# profil par une constante et preserve donc EXACTEMENT la falloff de l'artiste — c'est-a-dire
# l'ancrage. Un `shape<1` elargirait l'epaule et remonterait la RACINE, ce qui produirait « cheveux
# decolles du crane », etat que l'owner a deja vu et rejete. `cap=0.90` est celui de `rBoob`/`lBoob`,
# le seul que son oeil ait valide (« les seins, les mouvements subtils sont toujours OK »).
# `backHair2` est plafonne PLUS BAS que `backHair3` parce qu'il est plus pres de la racine : la
# monotonie du plafond le long de la chaine est la meme regle que le profil qu'on cherche a obtenir.
#
# ORDRE : ces `transfer` sont places AVANT le bloc `grade` (plus bas) a dessein — `grade` regradue
# la jonction cuir chevelu/meche sur les poids FINAUX. L'inverse rouvrirait la dechirure que
# `grade` vient de fermer.
