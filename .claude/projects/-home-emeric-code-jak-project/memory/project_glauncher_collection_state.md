Phase Glauncher-collection PASS 2026-07-02 (commit b806425f1). The Android APK's
behavior is ASSET-DRIVEN by which `<game>_assets.zip` bundles are present at build
time:
- **1 game bundled → SINGLE:** boots STRAIGHT into the game (no menu), per-game
  launcher name+icon. jak1 → "Jak & Daxter" (its shipped J&D placeholder icon,
  `android/app/src/main/res`, UNCHANGED); jak2→"Jak II", jak3→"Jak 3", jakx→"Jak X".
- **>1 → COLLECTION:** label "Jak and Daxter: The Recharged Jak-pot" + a boot
  SELECTION MENU (text rows, TOUCH tap + GAMEPAD D-pad up/down + Ⓐ/center/enter).

Mechanism / key files:
- `android/app/build.gradle.kts`: `detectBundledGames`/`appLabelFor` lambdas scan
  `src/<flavor>/assets-bundled/bundle/*_assets.zip`; per-flavor `resValue "app_name"`
  (app_name was REMOVED from strings.xml — a resValue + strings entry of the same
  name COLLIDE). `printGameDetection` task = build-time detection + dry-run
  (`-PdetectDir=<dir with 2 zips>` → COLLECTION). New `collection` flavor
  (org.opengoal.gk.collection).
- `LoaderActivity.java`: runtime detection via `getAssets().list("bundle")`; 1→direct
  boot, >1→menu. **Menu rows must stay `setFocusable(false)`** (else the framework
  eats DPAD_CENTER as a click on the view-focused row 0, ignoring the highlight —
  that was the bug the device caught). Debug override `getprop debug.opengoal.games`
  (comma list) forces the menu for an on-device dry-run without a 2nd real game.
  Per-game version stamp `.asset_bundle_stamp_<game>` but jak1 keeps the legacy
  `.asset_bundle_stamp` name so existing installs don't re-decompress.
- `MainActivity.java`: reads `EXTRA_SELECTED_GAME` (fallback R.string.game_name).
- `build_asset_bundle.sh`: also emits `bundle/<game>.manifest.properties`.
- Placeholder icons for jak2/jak3/collection generated by `.autoport/assets/gen_icon.py`.

No native change → libgk.so byte-identical → all jak1 fixes intact. Device-verified
on eae4df44 (single direct boot + menu-select via touch AND gamepad both boot jak1),
deploy_verify PASS. **STEP-1 for real multi-game:** build out/jak2 & out/jak3 arm64
asset sets, run build_asset_bundle.sh per game, stage the zips+manifests into
`src/collection/assets-bundled/bundle/`, `assembleCollectionDebug`. Rich menu
(bg/logos/idle Jak render) is future/backlog. See [[reference_real_device]],
