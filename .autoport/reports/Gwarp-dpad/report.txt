1. Where the options-menu stick->D-pad mapping lives (REUSED, not duplicated)
-----------------------------------------------------------------------------
- Java: android/app/src/main/java/org/opengoal/gk/TouchOverlayView.java updateStick() — menu branch
  converts the left-control drag into edge-triggered DPAD_UP/DOWN/LEFT/RIGHT onPadButton() presses
  (threshold dead = radius*0.62*0.22); gameplay branch sends analog LEFTX/LEFTY. The mode is latched
  per gesture at finger-down: previously `stickMenuMode = queryMenu()` (NativeGk.isInMenu()).
- Native: android/gk_android_main.cpp publishes g_overlay_in_menu on the GOAL thread every 15 frames
  from *progress-process* / *master-mode* (Gtouch-controls). The warp feature adds a parallel flag,
  same publisher, same consumer — the identical mapping is applied, nothing about the menu path moved.

2. Warp-UI-active detection (new)
---------------------------------
- The warp destination picker is a `warp-gate` process in state 'active (goal_src/jak1/levels/
  village_common/villagep-obs.gc:133 — reads cpad-pressed? left/right to cycle, circle to warp,
  triangle to exit). The engine exposes no global for "warp UI open", so gk_android_main.cpp
  (same 15-frame GOAL-thread publisher) walks the GOAL process tree from *active-pool*
  (brother @16 / child @20 are ppointer cells; process.state @deftype 56; state name @deftype 4;
  reads at deftype-4) looking for a live process whose type symbol is `warp-gate` and state name
  symbol is `active`. Result -> std::atomic g_overlay_in_warp -> JNI NativeGk.isInWarp().
- Fix found via prop-gated scan dump (debug.opengoal.gwarp.dump): empty GOAL tree links are #f (s7),
  NOT 0 — the first walk deref'd #f as a ppointer and self-looped in the symbol table (visited=2048,
  overflow=1920). s7-guarding cell+ref fixed it: visited ~127, overflow=0, warp-gate node resolves.
- Java: TouchOverlayView latches `stickMenuMode = queryMenu() || queryWarp()`; the glyph heartbeat
  ORs it too (left control draws the d-pad cross while the warp UI is up). Menu TAP routing stays
  gated on queryMenu() alone — warp only flips the stick mapping. Touch + D-pad/gamepad unchanged
  (additive; the dpad path is the same onPadButton one the menus use).
