WHAT THE MENU IS
  After the title flythrough, START opens the `progress` process on
  (progress-screen title) (title-obs.gc activate-progress). Its visible 2D draws
  at the title screen are:
   (a) SPRITES (sparticle particles[]): tint backdrop (part 337), L panel (335),
       R panel (336). Positioned by progress.gc::adjust-sprites; widened (tint) by
       progress-part.gc FUNCs. [These are what the prior PART check measured.]
   (b) TEXT (font draw-list): the option column NEW GAME / LOAD GAME / OPTIONS /
       SECRETS / QUIT GAME / BACK, drawn by progress-draw.gc::draw-options via
       print-game-text -> draw-string (font.gc). [The layer the PART check MISSED.]
   (c) ICONS (icons[]): eco/fuel-cell merc icons — parked off-screen (init x=-320)
       in the title menu (they belong to the in-game progress/pause menu).

HOW EACH DRAW'S ON-SCREEN X IS DETERMINED (so the numbers are interpretable)
  - SPRITES: each particle pos.x = init-pos.x - 256 (adjust-sprites:517); the
    sprite3_3d.vert shader maps user-hvdf.x = pos.x+2048 to NDC.x = pos.x/256 with
    NO aspect term. So pos.x (offset-from-centre) is the on-screen X; "bunched"
    means pos.x -> 0.
  - TEXT: each string's font-context origin.x is the virtual X; inside draw-string
    origin.xy is multiplied by *video-parms* relative-x-scale (vf1 = video-parms+64)
    and then by the font matrix (*font-default-matrix*, whose vector0x is also set
    to relative-x-scale). relative-x-scale = aspect-ratio-reciprocal = (4:3)/(20:9)
    = 0.6 at 20:9 — it deliberately keeps 2D content proportional (a central band).
    The menu's own widescreen nudge is left-x-offset (adjust-ratios), which feeds
    origin.x = (literal x-off - left-x-offset). So on-screen X is fully determined
    by {origin.x, relative-x-scale, font-matrix[0][0], left-x-offset}.
  - The aspect ENUM (get-aspect-ratio) is forced to aspect4x3 every frame at the
    title by pckernel.gc:277 (set-hud-aspect-ratio 'aspect4x3) on BOTH x86 and the
    device, so the enum is NOT a divergence axis here.

METHOD
  x86: instrumented HEAD (build-x86) — temporary read-only (format 0 "GTEX ...")
       dumps added to draw-string (font.gc) and adjust-sprites (progress.gc) print
       each menu string's origin.x + the once-per-frame menu state; recompiled live
       over the goalc listener ((lt)+(build-game)+(ml ...)), aspect forced to 20:9,
       menu opened with a real START (xfocus_tap 28). Captured from gk stdout.
  original-x86: the PRISTINE gold build (.autoport/gold/gk, 704972dd6) run the same
       way at 20:9 (NEVER instrumented — .autoport/gold stays byte-clean). The menu
       source files (progress*.gc, text.gc, font.gc, video.gc) are byte-identical
       HEAD-vs-gold (git diff empty), so our-x86 text behaviour == original by
       construction; gold is run independently to confirm.
  device: the instrumented consistent HEAD arm64 set built + deployed to eae4df44
       (deploy_verify PASS, 28/28 CGO byte-identical); the title menu opened via
       cpad inject; GTEX harvested from logcat. Native panel 2400x1080.
