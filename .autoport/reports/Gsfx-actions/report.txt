--------------------------------------------------------------------------------
ROOT CAUSE (arm64 codegen) — proven by disassembly
--------------------------------------------------------------------------------
sound-name is (deftype sound-name (uint128) ...) — a 128-bit VALUE type. It is
passed BY VALUE in a SIMD/XMM-model register. In goalc, register ids are
x86-model THROUGHOUT (XMM0..XMM15 = ids 16..31; the AArch64 bank split is encode-
time only). Register::is_gpr(ARM64) wrongly returns true for the entire id range
0..31 (it tests X0..X30 = native ids), so it ALSO matches the x86-model XMM ids.
The function/method ARGUMENT classifier in goalc
  goalc/compiler/compilation/Function.cpp (defun args) and
  goalc/compiler/compilation/Type.cpp     (defmethod args)
used  `is_gpr(m_instr_set) ? GPR_64 : INT_128`,
so on arm64 EVERY 128-bit value argument was mis-classed GPR_64. A disassembly
of a minimal repro (uint128 arg, intervening call, store into a field) shows:
  BEFORE: fmov x3, d17        ; mov igpr-3, igpr-0  -> arg TRUNCATED to 64-bit GPR,
          ...                  ;   high 64 bits lost + value clobbered across the call
  AFTER : mov v24.16b, v17.16b ; mov ii128-3, ii128-0 -> FULL 128-bit value in a V reg,
          str q24, [sp,#-0x10]!;   saved across the call, then
          str q24, [x16,#0x10] ;   FULL 128-bit store of the name. No truncation.
This is the A33-flagged x86-model-vs-arm64-native id inversion, fixed there for
is_128bit_simd but left in place for the argument classer.

THE FIX (translation layer only; goal_src untouched, 1-to-1)
  Classify a 128-bit value argument by is_128bit_simd (already x86-model-correct
  on BOTH backends, and already used for the RETURN value), not by the arm64-
  broken is_gpr:
    -  arg_regs.at(i).is_gpr(m_instr_set) ? RegClass::GPR_64 : RegClass::INT_128
    +  arg_regs.at(i).is_128bit_simd(m_instr_set) ? RegClass::INT_128 : RegClass::GPR_64
  Files: goalc/compiler/compilation/Function.cpp (2 sites), Type.cpp (2 sites).
  x86-NEUTRAL by construction: every x86 arg register is a GPR (ids 1..11) or an
  XMM (XMM1..XMM8 = ids 17..24); is_gpr and is_128bit_simd are exact complements
  over that set, so x86 RegClass assignments — and x86 bytes — are unchanged.

CONCLUSION
  The owner's silent action SFX were one symptom of a single goalc arm64 defect:
  128-bit (uint128 / sound-name) VALUE arguments were truncated/clobbered because
  the argument classer trusted the arm64-broken is_gpr. The one-line-per-site fix
  (use is_128bit_simd, matching the return-value classer) makes arm64 == x86 for
  every 128-bit-argument function — crate/orb/eco and all in-game positional SFX
  now transmit their correct names and play. goal_src stays byte-identical (1-to-1).
