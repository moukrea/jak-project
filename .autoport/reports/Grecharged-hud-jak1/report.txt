== BUG FOUND & FIXED THIS PHASE (x86-first verification catch) ==
Toggling recharged-hud? OFF while the eco gauge was VISIBLE (carrying eco) SIGSEGV'd
deterministically (2/2 repros, core rip in GOAL heap, stack full of enter-state/handler
frames). Mechanism: the engine hud 'hide-quick handler (hud.gc hud-arriving, shared by
hud-in) re-enters (hud-update self) BEFORE its (go hud-hidden) lands; the recharged-power
hud-update OFF branch re-sent 'hide-quick since hidden? was still false -> infinite
synchronous self-recursion -> stack overflow. Fix: gate the re-send on the handler's
last-hide-time stamp ((!= last-hide-time (current-time))), hud-classes-pc.gc
hud-recharged-power hud-update. The heart element was already recursion-safe (its
active-flag clears before the send). VERIFIED: the exact crashing sequence (ON + eco +
toggle OFF with the gauge visible) re-run after the fix — GK ALIVE at the crash beat,
zero new cores (previously 2/2 SIGSEGV). A player toggling the menu OFF while carrying
eco would have hit this on device.
