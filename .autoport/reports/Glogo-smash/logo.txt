--------------------------------------------------------------------------------
WHAT THE "SMASH" IS (goal_src/jak1/levels/title/title-obs.gc)
--------------------------------------------------------------------------------
The boot title path is the `logo` process: startup state plays the spool anims
in order:
  1. "logo-intro"   (Naughty Dog logo beat) — the logo-black (*logo-black-sg*) +
     logo-volumes (light-rays) slaves are ALIVE (blk=1 vol=1), bg-a fades 1->0.
  2. at the end of "logo-intro" the black/volumes slaves DEACTIVATE (blk 1->0,
     vol 1->0) — THE REVEAL ("breaking the black screen").
  3. "logo-intro-2" (the JAK&DAXTER logo SMASH) plays, fn (anim frame-num)
     advances; village displays at its frame 400 -> the flythrough.
  4. -> idle / "logo-loop" (the title attract loop).
The `logo` :post force-sets the main-joint placement (overall on-screen position/
scale of the logo + its black/volumes slaves) every frame.

Dumped fields (temporary (format ...) in logo startup :post + a startup-entry
marker; REMOVED after capture; .autoport/gold left pristine; v033 source restored):
  GLOGO st=<state> an=<spool anim> fn=<anim frame-num> blk=<logo-black alive 0/1>
        vol=<logo-volumes alive 0/1> bga=<bg-a>
  GLOGM mjtx,mjty=<main-joint trans x,y> mjsx=<main-joint scale x> asp=<aspect enum>

--------------------------------------------------------------------------------
REGRESSING-EDIT ANALYSIS (the prime suspect, named + CLEARED)
--------------------------------------------------------------------------------
Prime suspect (named in the phase): the Gtitle-pixelmatch 16x9 main-joint HACK in
the logo `:post`. The pristine code branches the main-joint placement on the aspect
ENUM: (if (= aspect 'aspect16x9) [scale 0.87, offset 2048,-1228.8] [scale 1.0,
centered]). Gtitle-pixelmatch HARDCODED the 16x9 branch unconditionally (the device
boots with aspect4x3 because the Android pc-get-window-size override is stubbed, so
the pristine branch would have placed the logo centered/4:3 -> the pixel-mismatch
that Gtitle-pixelmatch fixed).

Investigated and CLEARED as the smash break:
  - The hardcode does NOT freeze or break the smash: BOTH pristine and our build
    force-set the main-joint every frame (only the VALUES differ); the smash anim
    (logo-intro-2) is driven by the skeleton/spool, NOT the main-joint. Dumps
    confirm fn advances identically with the hardcode in place.
  - The numeric main-joint is IDENTICAL on original-x86 (which runs aspect16x9 ->
    pristine branch -> 2048,-1228.8,0.87) and on our build (hardcode -> the same
    values). So for the SMASH the placement matches the original 1-to-1.
  - The hardcode is a LATENT x86-only 1-to-1 imperfection: on an x86 window that is
    NOT 16:9, our build forces 16x9 placement where pristine would center it. It
    does not affect the device (device IS widescreen; placement is correct and was
    pixel-matched by Gtitle-pixelmatch) and does not affect the smash. It was NOT
    reverted to pristine because a bare revert would REGRESS the proven
    Gtitle-pixelmatch device logo placement (device stays aspect4x3 -> pristine
    branch would mis-center the logo), and the methodology-correct alternative
    (drive the Android aspect enum from the real window so the pristine branch
    produces 16x9) carries menu blast radius (Gmenu-ui-placement is tuned for
    aspect4x3 + the float ultrawide path) and is out of scope for a "logo smash"
    phase where the smash is not broken. The hardcode also predates the
    Glogo-smash supervisor anchor, so it is not a change introduced by this phase.

No goal_src edit was made (temporary instrumentation removed; git status clean).
Fix lives entirely in the (correct) existing build; the device persistently shows
the matching smash via the consolidated known-good set.
