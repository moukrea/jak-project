====================================================================================
PLACEMENT MECHANISM — driven by the grass GROUND TEXTURE (programmatic, no hand-authoring)
====================================================================================
At level-load, GrassRenderer scans the TRAINING level's loaded tfrag geometry
(Loader::get_tfrag3_level("training") -> tfrag3::Level, highest-detail tfrag_trees[0]).
For each StripDraw it reads the bound texture name via
lev->textures[draw.tree_tex_id].debug_name and keeps ONLY draws whose texture ==
"tra-grass" (the training grass ground texture, tpage training-vis-tfrag, per
recharged_assets/grass_reference/MANIFEST.md). It reconstructs that draw's triangles
from the unpacked strip index buffer (UINT32_MAX restart), filters to walkable GROUND
(face-normal +Y dominant, |ny|/|n| > 0.7), and scatters grass instances RANDOMLY inside
each qualifying triangle by barycentric sampling. Placement is DETERMINISTIC (a 32-bit
hash of the index position seeds position/size/yaw/tint/curve/phase), so the field is
stable frame-to-frame (no shimmer). Density is tunable (DENSITY_PER_M2 = 45 tufts/m^2,
capped at MAX_INSTANCES = 120000). Positions sit on the actual triangle plane; vertices
are world-space (4096 GOAL units = 1 m), reused directly with the game camera.

DEVICE PROOF (logcat): "[recharged-grass] training: 1 tra-grass draws -> 120000
grass-blade instances". The training ground is one large tra-grass draw; the 45/m^2
density hit the 120000 cap -> dense, full coverage of the Geyser Rock lawn.
Hard-scoped to training only: get_tfrag3_level("training") is null in every other level,
so grass never appears elsewhere (PoC scope respected).

====================================================================================
INSTANCE / LOD ARCHITECTURE  (renderer-side; engine goal_src untouched)
====================================================================================
One per-instance VBO (world pos + height + yaw/tint/curve/phase), built once per level
load (cached on LevelData::load_id). Drawn every frame as TWO instanced passes over the
same instances (glDrawArraysInstanced, geometry generated from gl_VertexID — no per-vertex
buffer):
  * NEAR tier  (u_mode 0): individual 3D BLADES, 10-vert triangle strip.
  * MID  tier  (u_mode 1): grass CARDS = X-cross of two crossed flat quads, 12 verts.
  * FAR  tier            : nothing added — the original ground texture only.
LOD is a per-instance distance CROSSFADE in the vertex shader (camera-to-blade distance,
world units): blades fade out ~10->18 m; cards fade in ~9->18 m, hold, fade out ~35->55 m;
beyond that the vertex collapses off-screen (no fragments) so there is no hard pop. This
sells the intended illusion: a real lawn up close, believable filler at mid range, stock
game far away.

Hook: drawn at bucket 30 (SHRUB_GENERIC_LEVEL1, i.e. right after all opaque background,
depth buffer + game camera ready), mirroring the existing collision-mesh hack. Added in
BOTH renderers — desktop game/graphics/opengl_renderer/OpenGLRenderer.cpp AND the on-device
android/android_opengl_renderer.cpp — gated on Gfx::g_global_settings.recharged_grass.
World->clip transform is copied verbatim from collision.vert so grass lands on the exact
scene pixels. Depth test GEQUAL (reversed-Z) + alpha blend.

====================================================================================
BLADE LOOK PARAMETERS (the near tier — the PoC test)
====================================================================================
- FLAT COLOR, NO TEXTURE (per the PoC): grass-green vertical gradient (dark base ->
  bright tip) with per-blade TINT variation (brightness + slight hue), no sampler at all.
- Variable SIZE: per-instance height ~0.14..0.29 m (hash-driven), width tapers to the tip.
- Variable ORIENTATION: per-instance YAW (0..2pi), width axis rotated by yaw.
- Variable CURVATURE: per-instance bend amount; the blade is a curved 4-segment strip
  (bent forward as t^2 up its height), not a straight quad.

BREEZE (idle motion): per-instance PHASE offset + shader time -> each blade sways
independently (sin(time*1.6 + phase), growing toward the tip) — the field is NOT in
lockstep. Cards sway gentler (sin(time*1.0 ...)).

TRAMPLE (flatten under Jak): Jak's world position is pushed to C++ every frame
(pc-set-jak-pos! bridge, from (-> *target* control trans) in the pc-layer update-to-os).
The blade/card shader flattens + bends grass radially AWAY from Jak within ~2.2 m
(height pressed down + tip pushed outward, strongest at Jak, recovering to the edge).
Instant radial flatten with distance falloff (recovery-on-leave, as Jak's uniform moves).

====================================================================================
PERF (Adreno 618, Geyser Rock)  — fps cost
====================================================================================
Grass ON  (120000 instances, 2 instanced passes): reached ~59.7 fps in a clean steady
           window — i.e. PINNED at the 60 fps vsync cap, so grass has render headroom
           and did not prevent 60 fps.
CAVEAT (honest): this Redmi is a SHARED test device (a parallel emulator/workload runs
on it) and fps here is dominated by device-load + camera-view variance, NOT by grass:
spot windows ranged ~31–60 fps in BOTH states (OFF windows sampled 31/38 fps at heavier
post-load views; ON hit the 60 cap at a lighter settled view). A grass-specific fps delta
could therefore NOT be cleanly isolated on this device (grass obviously cannot make the
game faster — the OFF-lower readings are load/view noise). What IS established: grass ON
showed NO framerate regression at the cap and stayed fully playable. Cost controls are in
place and tunable — 2 instanced draws, gl_VertexID geometry (no per-vertex buffer),
density (45/m^2, capped 120k) and LOD distance bands, with far instances collapsing
off-screen so fragment cost stays low. OWNER PLAY-TEST is the final perf judge.
