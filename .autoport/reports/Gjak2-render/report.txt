1. THE gcommon SIGSEGV CEILING — FIXED (fault site no longer reached)
------------------------------------------------------------------------
The "gcommon SIGSEGV on a new jak2 codegen path" was a COMPLEX of causes, each
root-caused with device+qemu forensics and fixed in the TRANSLATION LAYER only:

* arm64 bug class #14 — STALE INSTRUCTION CACHE ON LINKED GOAL CODE (the core
  new class; commit a157ae909, game/kernel/jak2/klink.cpp): jak2_finish's
  CacheFlush(m_code_start, m_code_size) was CacheFlush(base, 0) — the fields are
  never assigned — so NOTHING invalidated the icache for freshly linked code.
  The v3 TOP_LEVEL segment is rewritten at the SAME reused KMALLOC_TOP address
  for consecutive objects and executed immediately: the CPU executed stale MIXED
  instruction streams (masks: method_set type=0 SIGABRT / BLR to bare unrebased
  offsets incl. into the 'type' metaobject / SIGBUS; memory always read back
  CORRECT — attempt-1's art-h probes had proven that without recognizing it).
  Fix: real-range CacheFlush of MAIN+TOP_LEVEL+DEBUG (v3) / object (v2); x86
  CacheFlush is a no-op so x86 behavior is byte-identical. Device result: the
  intermittent 18-32-object boot-link crash class GONE 5/5 runs.
  NOTE: jak1 has the same vestigial no-op flush (jak1/klink.cpp:623) — the
  probable root of the F1e "~1-in-6 link-time boot-flake"; left untouched
  (jak1 locks), needs its own phase.
* jak2 arm64 mips2c wiring (ee473f3c2): game-aware arm64 table (jak2 link-
  callback map, per-game trampoline arena/noop/allowlist with jak2 Symbol4
  idiom), a11 impl serves jak2, 27 jak2 mips2c TUs compiled into both arm64
  builds. Killed the deterministic qemu 421-object SIGILL
  (adgif-shader<-texture-with-update! fn-ptr=0): qemu now links ALL 473.
* Android jak2 pc-* surface bind (a9ae376e6): 112-name binder (harness
  lockstep) restored in the jak2 pre-kernel hook (349 -> 483 links) +
  draw-pc-fps-counter bound (autoport jak1 pc-layer feature leaking into jak2
  via borrowed pckernel-common.gc — the first-render-dispatch fn-ptr=0).
* Level-heap exhaustion (4b56d7de6, goalc arm64-only defconstant override
  LEVEL_PAGE_SIZE_KB 126->168): arm64 level code (~1.67x x86) silently
  overflowed ctywide's ~4.3MB slot via klink's direct cursor advance ->
  entity-links-array kmalloc FAILED ("!alloc mem" is the failure print) ->
  level.entity=0 -> "ctywide has no entities!!" (break!). x86 output stays
  byte-identical (override gated on InstructionSet::ARM64).
* Suspend-budget pad (b1179db30 + 2n+128): jak2 engine tunes per-process
  suspend backups for x86/MIPS frame density (vehicle.gc sets 16 bytes!);
  arm64 frames overflow them -> thread-suspend (break). goalc arm64-only macro
  shadow of stack-size-set! call forms; x86 registers no macro.
* Per-frame jak1 repair canaries gated to jak1 (GCINE3-DEACT @0x191240,
  GMATCH-RFTD @0x18aee4, + 5 crash-repair handlers + GSPARK/A38 diag blocks):
  on jak2 those jak1-KERNEL.CGO addresses land in the SYMBOL TABLE / unrelated
  data — the per-frame snapshot-restore was actively CORRUPTING live jak2
  memory (observed reverting a legit symbol write, then new_type abort).
* jak2 VAG stream glue (1f3faa463): ENG fallback for language-suffixed VAGWAD
  (French device asked VAGWAD FRE; Android bundle ships ENG only) + drop-if-
  unresolved + open_fr null-guard (was: null FileRecord deref on the fakeiso
  pool worker, fault=0xc). Desktop-neutral.
