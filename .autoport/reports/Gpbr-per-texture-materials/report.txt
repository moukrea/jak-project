1. THE TANGENT FRAME, MEASURED PER FACE AND PER TEXTURE — AND THE ONE THING THAT WAS NEVER COUNTED
====================================================================================================

1.1 THE MECHANISM, FROM THE CODE

The bitangent the parallax march and the normal-map decode are built on is

    T = normalize(v_tangent.xyz - N * dot(N, v_tangent.xyz));      pbr_fused.glsl:17
    B = cross(N, T) * (v_tangent.w < 0.0 ? -1.0 : 1.0);            pbr_fused.glsl:22  (before this cycle)

`.w` is produced once per VERTEX, at common/custom_data/TangentDerive.cpp:206:

    float handed = (N.cross(T).dot(bit_acc[i]) < 0.f) ? -1.f : 1.f;

`bit_acc[i]` is the SUM of the per-triangle bitangents of every face incident to that vertex. But
HANDEDNESS IS A PROPERTY OF A FACE — it is the sign of that face's UV Jacobian — and a vertex where
faces of both handednesses meet makes that sum a fight between them. Whichever sign wins, every
incident face of the other handedness renders its relief inverted in V. No bake can repair it: it is
a property of the AUTHORED UV LAYOUT. TangentDerive.cpp guards the DEGENERATE determinant (:98) and
gives the NEGATIVE one no treatment at all.

That population is not marginal on village1 (tools/tess_sign, round-28 census, verbatim):

    uv_tris_total=1351952  uv_tris_mirrored=621191  uv_tris_degenerate=153  uv_verts_handedness_split=63453

45.9% of the triangles carry a mirrored UV chart — which is NOT in itself a defect, a whole level may
be authored that way — and 63 453 vertices are handedness-SPLIT, which IS.

1.2 WHAT THE PREVIOUS INSTRUMENT COULD NOT SAY, AND WHY THAT MATTERED

tools/tess_sign already graded the frame per face corner (P_sign). But it EXCLUDED from its
denominator every corner whose vertex mixes handedness, on the correct ground that the per-vertex
format cannot express a right answer there. On village1 that is 33 484 corners, 3.54% of the
population — and an excluded corner is not a correct corner, it is an UNSCORED one. The corners that
actually render inverted were sitting in that bucket, invisible.

This cycle adds PF_sign to tools/tess_sign: the SAME predicate, over the ENTIRE population, no
exclusion. The existing P_sign block is untouched (the new block is self-contained and sits before
the exclusion), and the reference run reproduces every pre-existing counter to the digit — the diff
against the previous run is 39 lines, 36 of them the new section and 3 of them wall clocks.

====================================================================================================
2. THE FIX: THE TANGENT FRAME IS NOW READ FROM THE FACE, NOT FROM THE VERTEX
====================================================================================================

2.1 WHAT CHANGED, IN FIVE PROGRAMS AND NOWHERE ELSE

Handedness is the sign of a FACE's UV Jacobian. `.w` is one sign per VERTEX. The frame now takes
both the handedness AND the tangent direction from the face the fragment (or the patch) belongs to:

  fragment sites — pbr_fused.glsl (the chunk tfrag3.frag / etie_base.frag / tie_wind.frag /
  shrub.frag all include) and tfrag3.frag's standalone rt-OFF PBR path:

      vec3 fdPx = dFdx(v_fringe_rel), fdPy = dFdy(v_fringe_rel);       // UNIFORM control flow:
      vec2 fdUx = dFdx(tex_coord.xy), fdUy = dFdy(tex_coord.xy);       // dFdx inside a branch is
      float fdetJ = fdUx.x*fdUy.y - fdUx.y*fdUy.x;                     // UNDEFINED in GLSL ES
      vec3 fdPdu = ( fdUy.y*fdPx - fdUx.y*fdPy) / fdetJ;
      vec3 fdPdv = ( fdUx.x*fdPy - fdUy.x*fdPx) / fdetJ;
      if (dot(fTuv, fdPdu) < 0.0) fTuv = -fTuv;                        // bank-2 bit 2
      float fhs = dot(cross(N, fTuv), fdPdv);
      fBuv = cross(N, fTuv) * sign(fhs);                               // bank-2 bit 1

  tess-eval site — tfrag3_tess.tese: no derivatives exist in that stage and none are needed. The
  PATCH IS THE ORIGINAL TRIANGLE, so tc_world[0..2] / tc_texcoord[0..2] give the Jacobian exactly.

Both are inverses of the FULL 2x2 screen->UV Jacobian, so what they recover is the true geometric
dP/du and dP/dv at that fragment: every camera-dependent part cancels.

2.2 THREE PROPERTIES THAT MAKE THIS SAFE, AND ONE OF THEM FIXES A SECOND DEFECT FOR FREE

  (a) NO INTRA-TRIANGLE DISCONTINUITY. Handedness is CONSTANT over a triangle (its UVs are affine
      there). This is not the derivative-derived tangent DIRECTION that REOPEN#9 removed because it
      jumps at every edge and reads as facets — only the SIGN is taken, and it differs from the
      baked one only where the UVs genuinely mirror, which is where it must.
  (b) NO QUAD-STRADDLING HAZARD. A partially covered 2x2 quad is shaded with the SAME primitive's
      attribute plane extrapolated into the helper lanes, so dFdx/dFdy belong to ONE triangle. The
      fallback to the baked `.w` on a degenerate Jacobian is a belt, not the load-bearing part.
  (c) THE BITANGENT IS NOW INVARIANT UNDER N -> -N, BY ALGEBRA, AND THAT KILLS A WHOLE CLASS.
      fTuv = normalize(v_tangent.xyz - N*dot(N,v_tangent.xyz)) is even in N. Under N -> -N,
      cross(N,fTuv) flips AND fhs flips, so fBuv = cross(N,fTuv)*sign(fhs) is UNCHANGED. With the
      per-vertex `.w` it was ODD in N — and tfrag3.frag:710 view-flips its surface normal
      (`if (dot(Nsurf, V) < 0.0) Nsurf = -Nsurf;`), which made the frame's handedness A FUNCTION OF
      WHERE THE CAMERA IS on every double-sided level triangle. That is « ça marche d'un côté mais
      pas de l'autre » read literally, and it is now impossible by construction rather than by
      tuning. It is a PROOF, not a measurement: no camera-dependent quantity can be counted offline.

2.3 CONFINEMENT — WHAT MOVES AND WHAT CANNOT

A corner where the derived sign already equals the stored one is bit-identical: the same expression
multiplies the same vector by the same +/-1. So the change is confined, exactly, to the corners the
census counts as wrong:

    corners the fix repairs : 1591 (handedness) + 1052 (direction) = 2643   of 946722  = 0.2792%
    corners left BIT-IDENTICAL                             944079           of 946722  = 99.7208%
    PF_sign, before                                         99.7208%
    PF_sign, after (both terms zero by construction)       100.0000%

The "after" figure is not a re-measurement, and it is not offered as one: it is what the predicate
BECOMES when the quantity it tests is derived from the face it tests against. What the offline
census supplies is the SIZE of the moving population, which is the falsifiable part — if the fix
were wrong, it would be wrong on 0.28% of corners and on no others.

2.4 THE A/B KILLSWITCH, AND WHY IT OPENS A NEW BANK

`u_pbr_bisect`'s 31 bits are ALL taken (1 .. 1073741824, scanned across every *.glsl/*.frag/*.vert/
*.tesc/*.tese before the line was written; 2147483648 does not fit a GLSL ES signed int). Rather
than overload a used bit — the confounding trap the bit-33554432 note in pbr_uniforms.glsl was
written to prevent, and which once merged two A/Bs into one frame — a second bank is opened:

    u_pbr_bisect2  (prop debug.opengoal.pbr.bisect2 / env OG_PBR_BISECT2, default 0 = the fix ON)
        1 = per-FACE tangent HANDEDNESS off  -> back to the baked per-vertex .w
        2 = per-FACE tangent DIRECTION  off  -> back to the baked per-vertex T

so the owner can put either half of this cycle back with one setprop, at his own vantage, with no
rebuild.
