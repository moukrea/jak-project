ITEM 3 — RIFT-GATE GLOW too bright pre-metalheads   [new root cause landed; brightness = owner]
The prior depth-FBO internalformat tweak did not do it. Re-diagnosed the GlowRenderer occlusion probe:
the probe FBO's packed DEPTH24_STENCIL8 texture was attached at GL_DEPTH_ATTACHMENT (GlowRenderer.cpp:202)
while the main render framebuffer attaches its depth-stencil at GL_DEPTH_STENCIL_ATTACHMENT
(OpenGLRenderer.cpp:923). On strict GLES3/Adreno a glBlitFramebuffer(GL_DEPTH_BUFFER_BIT) from a combined
depth-stencil source into a depth-ONLY-attached packed dest is rejected -> the probe depth stays stale ->
GEQUAL occlusion probes always pass -> discard_flag ~= 1 -> glows read fully-visible/over-bright (the
rift/portal flare). FIX (renderer glue, Android-only effect, no-op on desktop GL which accepted either):
attach the probe texture at GL_DEPTH_STENCIL_ATTACHMENT so the GLES depth blit matches the source and the
occlusion probe occludes correctly. The glow-input values are identical on x86 and arm64, so this is a
GLES depth-copy correctness fix, not a glow-input change. The exact brightness level is the owner's eye
(Ghalo/sun methodology); if still hot, the next lever is a device probe-alpha dump at that beat.
