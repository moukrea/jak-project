1. THE FIRST x86-vs-arm64 DIVERGENCE + ITS ORIGIN OP (smoking gun)
================================================================================
Origin op: goalc's arm64 codegen for GOAL float min/max —
  scalar  fmin/fmax  (FloatMath MIN_SS/MAX_SS): x86 MINSS/MAXSS  vs arm64 FMIN/FMAX
  vector  .min.vf/.max.vf (VFMath3 MIN/MAX):    x86 MINPS/MAXPS  vs arm64 FMIN.4S/FMAX.4S

x86 (V)MIN/MAXSS/PS: result = (a OP b) ? a : b. The compare is FALSE when unordered
(a NaN is involved), so the result is the SECOND operand whenever EITHER input is NaN.
=> a collision clamp written `(fmax X 0.0)` SANITIZES a transient NaN X to 0.0 (FINITE).
AArch64 FMIN/FMAX implement IEEE min/max that PROPAGATE NaN.
=> the same clamp PROPAGATES the NaN on arm64.  THIS is the "x86 finite vs arm64 NaN" op.

The NaN itself is born (on BOTH backends, identically — matches original OpenGOAL) at the
UNGUARDED `vector-normalize!` (goal_src/jak1/engine/math/vector.gc:599): normalizing a
degenerate / zero-length collision separation vector = 0/0 = NaN. That transient NaN flows
into reaction clamps `(fmax X const)`, notably collide-shape-moving-angle-set!
(collide-reaction-target.gc:13) `(fmax touch-angle (vector-dot ... (vector-normalize! ...)))`
— x86 returns the finite touch-angle, arm64 returns NaN -> wrong wall/ground classification
-> wrong (finite or rejected-cell) collision push-out: clip / eject / under-map / invisible
wall, only at degenerate/grazing contacts (ledges/edges), matching the owner's
"ça projette / at borders / intermittent."

3. AFTER the fix — arm64 == x86
================================================================================
The fix re-emits arm64 min/max as x86's "return operand-2 on unordered":
  scalar MIN: FCMP dst,src ; FCSEL dst,dst,src,MI
  scalar MAX: FCMP src,dst ; FCSEL dst,dst,src,MI
  vector MIN: FCMGT v0,src2,src1 ; BSL v0,src1,src2 ; MOV dst,v0
  vector MAX: FCMGT v0,src1,src2 ; BSL v0,src1,src2 ; MOV dst,v0
  AFTER:
    arm-fixed vs x86 = BYTE-IDENTICAL on ALL 576 rows (0 differences) — arm64 == x86,
    NaN handling now matches the oracle exactly (FINITE both where x86 is finite, NaN both
    where x86 is NaN). No NaN is produced where x86 is finite.

In-game AFTER (device, fixed full-consistent CGOs, deterministic warp + aggressive degenerate-
contact drive): collision angles (surface/poly/touch) and all 4 normals stay FINITE
(angle_nan_frames=0, normal_nan_frames=0, finite=1), velocity finite, crash-free, app
foreground throughout (dev_after.log). arm64 collision == x86 (finite both, 0 NaN reaching
the collision response).

genuine out-of-range/+Inf conversions); not reverted (reverting would re-introduce a real

5. RULED OUT (so fmin/fmax is the only remaining arm64-vs-x86 float divergence)
================================================================================

- Collision VELOCITY (transv) and normals/angles: FINITE on BOTH backends even under aggressive
