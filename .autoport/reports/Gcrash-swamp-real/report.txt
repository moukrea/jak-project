## ROOT NAMED — the real crash sink (by analysis; differs from the drive-hook sink 543b7739b cured)
Because real-input LOAD+LINK is crash-free, the owner's crash is at swamp reaching status 'active
(actor birth with Jak present) — "as the swamp loads/displays". Ranked candidates (all arm64-only;
x86 runs the same route crash-free — the oracle):

      kermit.gc:386  `(mod (+ arg2 1) 3)`  — arm64 integer-modulo-returns-quotient class (bug class
      #13, the msub-missing modulo already seen title-camera-side); and kermit.gc:1059 inv-scale
      `(/ 1.0 f0-16)` 1/0 -> NaN bone matrix (the Gcine-pose matrix-inv-scale class). These fire only
      once the actor is ALIVE with the player in-region = exactly "swamp active", which the drive-hook
      (teleport, never truly active with a live player) and my swim (never active) both skip.
  #2  LOOKUP-COVERAGE-GAP the 543b7739b fix does NOT cover: part-spawner::init-from-entity!
      (generic-obs.gc:805) and effect-control (effect-control.gc:142-145) cache a RAW
      *part-group-id-table* slot pointer EXTERNALLY (into the res-lump / the persistent entity `value`
      field). The fix invalidates table SLOTS (object-in-memcpy-range) but never these external caches;
      the validator part-group-pointer? (sparticle-launcher.gc:83) checks array BOUNDS only, so a
      stale cached pointer to a cleared/re-registered slot passes and binds garbage. swamp-part
      (swamp-part.gc:11) is a part-spawner -> this path runs on swamp entry. Same fn-family as the
      drive-hook sink but a different, uncovered corruption source.
  #3  The fix guards only the MAIN + TOP-LEVEL segment memcpy (klink.cpp:324/346), NOT the DEBUG
      segment copy (klink.cpp:306).
