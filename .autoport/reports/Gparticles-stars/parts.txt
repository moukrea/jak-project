--------------------------------------------------------------------------------
THE METRICS (and why)
--------------------------------------------------------------------------------
vproc3d = count of VALID 3D sparticles transformed + written to *sprite-array-3d*
          vecdata THIS frame (counted inside the sp-process-block-3d mips2c body,
          game/mips2c/jak1_functions/sparticle.cpp, at the block_20 sqc2 vecdata
          emit). This is the contamination-proof "emitted/visible" metric:
            * builder NOOP'd  -> body never runs -> vproc3d = 0
            * builder REAL    -> vproc3d ~= alive 3D particle count (num-alloc)
          Measured identically on x86 (env OG_PARTS_DUMP=1) and arm64/device
          (prop debug.opengoal.gparts.dump=1) — SAME shared renderer/mips2c TU.

starc   = (-> *time-of-day-proc* star-count) = number of night-star sparticles
          SPAWNED (ramps 0->85 at night). Field offsets verified on all 3 builds
          (POFF hour=124 tod=140 starc=148 sunc=156). Star sprites only become
          VISIBLE when the 3D builder emits them (vproc3d>0); starc is spawn,
          vproc3d is draw.

a3d/a2d0= (-> *sp-particle-system-3d*/2d* num-alloc 0/1) = ALIVE particle count,
          read via the goalc LISTENER on x86 (non-invasive, gold stays pristine).
          Used for the our-x86 == original-x86 1-to-1 proof. (On device the
          symbol-base read is unreliable -> a3d shows 0 there; the device truth
          is vproc3d, which is base-pointer-independent.)

sub3d   = per-frame Sprite3 Mode3D submitted sprites. REPORTED BUT NOT TRUSTED as
          an alive metric: when the builder is noop'd, the never-freed stale
          *sprite-array-3d* alloc is STILL emitted (garbage vecdata), so sub3d
          stays HIGH (3072 on device BEFORE) even with ZERO live particles. This
          is exactly the contamination that made the Gd2 renderer/builder proxy
          lie. vproc3d does not have this failure mode.
