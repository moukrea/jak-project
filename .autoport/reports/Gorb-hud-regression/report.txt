== 2. Why the render-split broke it ==
The white egg is not the orb itself: the icon is TWO layers — the opaque, depth-writing 3D orb
model (Generic2, bucket 46, alpha SRC_SRC_SRC_SRC = GL_ONE/GL_ZERO, ztest GEQUAL + zwrite ON,
mode 0xfe1a00dd) and a white 'hud-egg' GLOW SPRITE behind it (progress-part.gc parts 1983/1986,
sprite bucket 66, ztest GEQUAL). In the single-FBO pipeline the orb's depth write rejects the glow
sprite on the orb's pixels, so the glow only peeks around the edge. The Grender-split composite
(begin_2d_ui_pass/begin_ui_pass) upscale-blits the scaled scene COLOR-only into the native UI FBO
and CLEARS ITS DEPTH TO 0 before the 2D pass — the orb's depth footprint is lost, the glow sprite's
GEQUAL ztest passes everywhere, and it overdraws the composited orb -> the WHITE egg. Identical
visual to the pre-Gorb-icon bug (there the missing orb draw exposed the same glow sprite), entirely
different mechanism. It hit EVERY interface because every orb icon site (HUD counter, progress
menu, save screens) uses the same generic-hud draw + glow-sprite pair, and the device keeps the
split active even at RENDER SCALE 100 because game-size 640x480 < native draw region.
CAUSAL PROOF (x86-first, shared renderer code — not an arm64 bug): same binary, x86 desktop,
Geyser pause menu: render-scale 50 (split ACTIVE) = white egg (x86-orb-closeup.png); default 100
(split INACTIVE) = textured amber orb (x86-orb-closeup-rs100.png).

== 3. The in-split fix (split kept) ==
Generic2's HUD-flagged draws are screen-space UI by construction (hud matrix). When the split is
armed (jak1 + begin_2d_ui_pass set), Generic2::do_draws now STASHES them (compact-copied
verts/indices + per-batch DrawingConfig — the shared buffers are rebuilt by later generic buckets)
instead of drawing them into the scaled scene FBO. Both frame orchestrators (OpenGLRenderer and
AndroidOpenGLRenderer) REPLAY them at the end of begin_ui_pass — after the composite, BEFORE the
sprite HUD group — into the native UI pass. This (a) restores the depth relationship: the orb
writes its depth into the UI FBO, so the hud-egg glow sprite is depth-rejected exactly as in the
single-FBO pipeline, and (b) renders the orb icons native-crisp like the rest of the UI. The replay
saves/restores the caller's GL program + VAO (it runs inside Sprite3::render via the hook; the
first attempt without the restore corrupted Sprite3's uniforms — 495,539 GL_INVALID_OPERATION on
x86 + a missing amber menu ring — both zero after the restore). Split-inactive and jak2+ paths are
byte-identical to before. Files: Generic2.h, Generic2_OpenGL.cpp, OpenGLRenderer.cpp,
android_opengl_renderer.{h,cpp}. No goal_src change (engine source untouched, 1-to-1 preserved);
.autoport/gold untouched (pristine).
