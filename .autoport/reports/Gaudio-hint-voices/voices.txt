--------------------------------------------------------------------------------
THE TRIGGER / ROUTE GAP (named)
--------------------------------------------------------------------------------
In-game tutorial/hint dialog VOICES (the `level-hint` "Sage/sidekick" speaker,
goal_src/jak1/engine/entity/ambient.gc:273-361, fired by level-hint-spawn from
crates.gc / orb-cache.gc / game-info.gc) play their speech as a STREAMED VAG:

  (format (clear *temp-string*) "spool-~S" name)                ; ambient.gc:287
  (sound-play-by-name (string->sound-name *temp-string*) ...)   ; ambient.gc:288

i.e. the voice name "spool-<VAG>" is built AT RUNTIME by string->sound-name (a
uint128 / `sound-name`) and passed BY VALUE into sound-play-by-name. In the C++
overlord (srpc.cpp:125) a "spool-" prefix routes the name to FindVAGFile ->
PlayVAGStream -> 989snd stream voice (tag 1).

Cinematic / cutscene voices take a DIFFERENT request path: str-play-async with a
plain STRING basename (load-dgo.gc:159, *play-str-rpc*), which copies the name
byte-wise — it never crosses a 128-bit-value-by-value boundary.

THE GAP: on arm64, goalc mis-classed the 128-bit `sound-name` VALUE arg as GPR_64
(is_gpr wrongly matched the x86-model XMM id range 16-31), so the runtime hint
name was TRUNCATED/CLOBBERED across the call (`fmov x,d`). The corrupted name no
longer began with "spool-" -> the srpc.cpp:125 prefix test failed -> FindVAGFile
was never called -> the in-game hint voice was DROPPED, SILENTLY, at the
`if (vagfile != nullptr)` guard. The cutscene voices (plain string basename) were
immune -> they kept playing. That is exactly the owner's symptom: "cinematic
voices work, the in-game hint/Sage voices don't."  The SAME 128-bit corruption
silenced ~68% of in-game positional action SFX (crate/orb/eco) on the same
sound-play-by-name path.

ROOT-CAUSE FIX (already in HEAD, goalc; goal_src 1-to-1): classify 128-bit value
args by is_128bit_simd (x86-model-correct on both backends) instead of is_gpr,
in goalc/compiler/compilation/Function.cpp + Type.cpp. x86 output byte-identical
(is_gpr/is_128bit_simd are exact complements over the arg-reg set).
THIS PHASE additionally hardens the route (libgk, srpc.cpp): a "spool-" voice that
fails to resolve in the VAG directory now logs lg::error `[hint-voice] ... DROPPED
(silent)` instead of vanishing without a trace — so the invisible-failure mode
that hid this bug can never be silent again.
