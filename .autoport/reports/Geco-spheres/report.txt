== Root cause (proven by x86-vs-device probe bracket) ==
CPU-side particle data was byte-equivalent to x86 at init (SPART-INIT), at post-field-init
(P1/SPART-204I) and post-orbit-init (P2/SPART-204Q) — then poisoned at birth-complete
(SPART-BORN): staging pos x/y and vel-sxvel rotated to ±1e9..1e13 same-magnitude pairs,
z preserved; NaN rotvel3d downstream in sp-orbiter. 102/102 eco orbit-sparkle births
poisoned on device, 0/270 on x86.

The one call between P2 and BORN is sp-rotate-system. In sp-launch-particles-var
(game/mips2c/jak1_functions/sparticle.cpp's launcher sibling,
game/mips2c/jak1_functions/sparticle_launcher.cpp), the binding REGISTRATION path decides
via `bnel s6, s7` ("system is-3d != #f?") whether to store the parent's 3D sprite or #f
into launch-state.sprite3d. On arm64 this full-64 compare MISSES #f (gpr s7 = full host
base, the is-3d #f = bare low-32 offset) — the identical bug class and the identical s6
register as the Gmenu-textures euler-convert fix 65 lines below it, which this site missed.
Result: every BOUND 2D particle's launch-state got sprite3d = the parent's 2D SPRITE; at
each bound child's launch, sp-rotate-system(staging, cpuinfo, 2d-sprite-as-transformq) read
the sprite's flag/rot-z/sy quad as a quaternion (rot 0-65536, sy ~thousands for a spinning
bigpuff cloud) -> w = sqrt(1-huge) = NaN -> garbage rotation matrix -> the child's staging
pos and velocity destroyed at birth. Children of SPINNING cloud parents (the bright
starflash cores, orbit sparkles, trails — the visible eco identity) died invisible;
children of the tiny static center dot got a near-identity garbage quat and survived —
exactly the dim smudge the owner saw. 38-41% of ALL orbiter particles (ambient included)
were NaN.

== The fix (translation layer only, 1-to-1 preserved) ==
game/mips2c/jak1_functions/sparticle_launcher.cpp, three #f-guards arm64-gated to the
established 32-bit gpr_addr compare (same pattern as the five existing fixes in the file);
x86 code is untouched (#else branches), goal_src untouched, golden untouched:
1. registration is-3d guard (root cause) — 2D systems store #f into sprite3d again;
2. block_41 launch-state #f guard;
3. block_41 sprite3d #f guard — 2D launches skip sp-rotate-system exactly like x86.
