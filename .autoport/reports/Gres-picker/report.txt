OWNER REFINEMENT (2026-06-30) — what this re-opened phase fixes
--------------------------------------------------------------
The prior Gres-picker build (90a7a1dce) shipped the NATIVE entry + per-aspect ladder +
persistence and the owner play-tested it: "otherwise perfect" — BUT the "NATIVE" entry was
the RAW PANEL SIZE (2400 x 1080) regardless of the chosen aspect ratio. On a 2400x1080
(~2.222:1) panel that is correct ONLY when the chosen aspect IS the panel's aspect; at 4:3
or 16:9 the panel size is the wrong aspect, so "NATIVE 2400 X 1080" sat above a 4:3 or 16:9
ladder — a label that did not match its own list.

Owner mandate: NATIVE must be the LARGEST resolution AT THE CURRENTLY-SELECTED aspect ratio
that fits inside the physical panel, and it must RECOMPUTE when the aspect changes:
  - chosen aspect WIDER than the panel  -> bound by panel WIDTH,  compute height;
  - chosen aspect NARROWER/taller       -> bound by panel HEIGHT, compute width;
  - chosen aspect == the panel's aspect -> the real panel size.
Owner's example: 1080-tall panel, choose 4:3 -> 4:3 is narrower than the 2.222 panel ->
height-constrained -> NATIVE = 1440 x 1080 (1080 * 4/3). Choose 16:9 -> 1920 x 1080. Choose
the panel's own aspect -> the real 2400 x 1080.


THE FIX (pc/ GOAL only; engine goal_src untouched -> gold oracle clean)
----------------------------------------------------------------------
One surgical change, goal_src/jak1/pc/progress-pc.gc :: build-resolution-options (1331).
Previously the NATIVE entry used the raw panel size (pc-get-active-display-size). Now the
function reads the panel as panel-w/panel-h, computes the panel aspect, and derives the
NATIVE entry as the largest aspect-correct rectangle that fits the panel:

    panel-aspect = panel-w / panel-h
    aspect       = (-> *pc-settings* aspect-ratio)          ; 4:3=1.333, 16:9=1.778, auto=panel
    fit-width?   = aspect >= panel-aspect
    native-w     = fit-width? ? panel-w : round(panel-h * aspect)
    native-h     = fit-width? ? round(panel-w / aspect) : panel-h

native-w/native-h are then used BOTH for the NATIVE entry AND as the ladder ceiling, so the
ladder (already generated at the current aspect) and the NATIVE entry are mutually
consistent. build-resolution-options re-runs every frame in respond-common, so the NATIVE
entry RECOMPUTES / re-filters LIVE the instant the aspect ratio changes — no menu re-open
needed. This is a 100% pc/ GOAL change: no C++, no engine goal_src, golden untouched. It
is the established CGO-only-on-fixed-libgk practice (the prior 3 Gres iterations all ran on
libgk b5a7bb03; this change touches no C++, so the same libgk is correct and consistent).

Math note: the ladder is unchanged in practice — at 4:3/16:9 the old raw-panel ceiling was
never the binding clamp (the panel-HEIGHT clamp ran out first), so only the NATIVE VALUE
changes; the new code also drops the old duplicate (e.g. 16:9 used to list NATIVE 2400x1080
AND a separate 1920x1080 ladder row — now NATIVE IS 1920x1080 and the ladder excludes it).
