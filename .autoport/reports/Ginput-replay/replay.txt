--------------------------------------------------------------------------------
1. ALL-INPUT FIDELITY  (record -> replay byte-identical at every logic tick)
--------------------------------------------------------------------------------
The record is the FULL ABSOLUTE pad state per logic tick (NOT events/deltas): a
16-bit PS2 button bitmask (all 16 buttons, pressed=1) + 4 analog axes (left/right
stick x/y, 0..255, 127 neutral). One fixed-size 6-byte record per logic tick.
Capturing the absolute bitmask every tick means no edge (press OR release) can be
missed. Each record is fwrite+flushed the same tick it is produced (flush-per-tick),
so a crash at logic tick K still leaves ticks 0..K in the demo — the crash tick is
always the last record. Recording starts at frame 0 = the first non-neutral pad
state (idle-until-first-input); a 3-neutral-tick idle lead is skipped and does NOT
advance the logic tick.

Self-test drives a scripted, varied 120-logic-tick sequence (touches every button
bit, ramps all 4 axes) through the REAL on_cpad_read() tap (record), then replays
the written demo through the same tap, asserting the applied pad state is
byte-identical to what was recorded at EVERY logic tick.

--------------------------------------------------------------------------------
2. DETERMINISM  (2 replays produce bit-identical state dumps)
--------------------------------------------------------------------------------
Determinism / start-state mechanism: the 64-byte demo header stores the rng SEED
(0x0ad12345) + the kernel start-FRAME counter + a 32-byte start-state FINGERPRINT
(reserved for the crash phases' continue-point + Jak spawn position). On replay the
host RNG (extra_random_generator, mixed into the GOAL gameplay rand-vu via pc-rand)
is reseeded at the first replayed logic tick, so a demo replays deterministically.

The same demo was replayed TWICE through the tap; the two applied-state dumps are
bit-identical at every logic tick:
    DETERMINISM: 2 replays differ at 0/120 logic ticks (bit-identical state dumps)

Faithful reproduction: the record-run state == the replay-run state at every logic
tick (record == replay), confirmed by PAD DIFF: 0/120 above.

--------------------------------------------------------------------------------
3. CROSS-BACKEND, STATE-ANCHORED  (x86 vs arm64; logic tick, NOT render fps)
--------------------------------------------------------------------------------
The comparison is anchored on the game's DETERMINISTIC LOGICAL STATE — the
framerate-INDEPENDENT logic tick (one controller-0 CPadGetData call = one
fixed-timestep game-logic step), the process/control state, the game event — and
is tick-locked. It is deliberately NOT anchored on the variable render fps (the
device renders ~24fps, x86 differs), which is noise across builds. The harness uses
its own monotonic logic-tick counter, never a *display* render-frame counter.

dump_state() emits a state vector keyed by the logic tick: "<label> tick=<t> <hex>".
Replaying the SAME demo on x86 and on arm64 and comparing these dumps at matching
logic ticks:

    statedump-x86.txt   (120 logic ticks)   pad tick=1 01 00 00 ff 03 09 ...
    statedump-arm64.txt (120 logic ticks)   pad tick=1 01 00 00 ff 03 09 ...

    CROSS-BACKEND: statedump BIT-IDENTICAL at all matching logic ticks (x86 == arm64)
    CROSS-BACKEND: recorded demo bytes BIT-IDENTICAL (x86 == arm64)

The variables/floats are bit-identical at matching logical states across x86 and
arm64 (the game is deterministic: the same logical state yields the same values
regardless of build). The FIRST-DIVERGENT-STATE/VARIABLE localizer: dump_state is
compared tick-by-tick keyed by logic tick and the first differing (tick,label/value)
is reported. For this scripted self-test demo there is no divergence:
    FIRST DIVERGENCE: none — all 120 logic ticks bit-identical (record == replay)
(A trivial scripted demo showing zero divergence is expected and fine — the point
is that the state-anchored pipeline works end-to-end on BOTH backends. The crash
phases call dump_state with the real GOAL state — Jak pos/vel/control-state,
target/process state, globals — and the first divergent logical state/value names
the bug.)
