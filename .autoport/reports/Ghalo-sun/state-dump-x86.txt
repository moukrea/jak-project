== Ghalo-sun — x86-FIRST sun-cycle STATE dump: our-x86 vs ORIGINAL-x86 ==

Methodology (owner directive 2026-06-19): deterministic GOAL STATE dump of the title
sun-cycle, NOT screenshot pixel-diffs. The title sun glow is the `group-sun` additive
billboard (weather-part.gc:482) spawned/killed by `time-of-day-update`
(time-of-day.gc:44-49) and SIZED by `sparticle-track-sun` as `128 * (-> *time-of-day-context*
sun-fade)` (weather-part.gc:469). We dumped, across the full day/night cycle:
  - time-of-day (tod, the sun phase),  day counter
  - sun-count   (the spawn GATE: 1 = sun particle spawned, 0 = killed)
  - sun-fade    (sf, the GLOW SIZE: glow scale = 128*sf)
  - current-interp (cint, the level-mood blend that drives sf)
  - the sun launch-control per-emitter flags (PRT f0/f1/f2: 1=launcher-active,
    3=launcher-active+particles-active  => the particle is actually LAUNCHED/re-armed)
  - current-sun sun-color (scol, the glow COLOUR/LIGHT state) + env-color (ecol)

  - OUR x86      : build-x86/game/gk on current HEAD source. Dumped via a TEMPORARY
                   `ghalo-sun-dump` (format 0 -> stdout) added to the title attract
                   :trans, forcing fast time so several day/night cycles run in one
                   attract. Instrumentation has since been REMOVED (see fix-summary).
  - ORIGINAL x86 : /home/emeric/code/jak-original-v033 (v0.3.3, c4bc4d3ff) — PRISTINE.
                   No source edits; the same persistent runtime fields were READ over
                   the goalc listener (build-game intern + `(format #t ...)`). The
                   original repo stayed git-clean (empty `git status --porcelain`).

Key fact: sf == cint EXACTLY. The glow SIZE is driven by the mood blend
`interp(L0='title' sun-fade 0.0 , L1='village1' sun-fade 1.0) = cint`, i.e. by the attract
CAMERA position (level distances), NOT by sun elevation. It oscillates 0.5<->1.0 and
periodically floors at 0.5 and RE-BLOOMS as the looping flythrough moves the camera. This
is the intended upstream behaviour.
