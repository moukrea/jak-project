== WHAT WAS BATCHED / CHANGED (renderer/GLES only; goal_src + gold untouched) ==
1. ec6e8d2eb  A35-PERF per-bucket profiler dump (the profile above).
2. 84ecbda22  Draw MERGE in the no_multidraw path (TFragment/Tie3 base+envmap/
   Shrub): consecutive draws sharing texture+mode merge into ONE glDrawElements.
   Safe because the single-draw index builders pack ranges adjacently and every
   strip carries a trailing primitive-restart index (verified in TFrag3Data.cpp
   unpack + extract_shrub.cpp); each merge re-checks range contiguity, and
   double-draw (AFAIL) draws are issued alone preserving exact draw order.
   Effect: village1 l1-tie 109->76 draws while driving; near-zero merges at full
   static visibility (adjacent draws rarely share state there) — which is why the
   phase pivoted to state-churn/sync elimination, the true cost.
   Plus: alpha_min/alpha_max uniform locations CACHED per program
   (setup_tfrag_shader did 2 glGetUniformLocation string lookups PER DRAW).
3. 1f504fcf8  Merc2 per-draw redundant-state elimination (state sort/cache
   class): ignore_alpha/decal/gfx_hack_no_tex uniforms, setup_opengl_from_draw_
   mode (~12 GL calls incl. 4 glTexParameteri), and glBindBufferRange skipped
   when unchanged vs the previous draw (setup key includes the bound texture,
   since setup writes wrap/filter onto the texture object).
4. f6e32f4bf  Merc per-flush driver-sync DEDUPE: the F1a/F1d Adreno BO-defuse
   read-maps (glMapBufferRange READ = pipeline sync) ran per level bucket per
   flush across 8 merc bucket renderers; now once per (level, load_id) per FRAME
   via the shared Merc2 core — the defuse contract (level BOs mapped once per
   frame before its first merc draws, per F1a run-16/17 evidence) is preserved,
   the crash defusal stays armed. VAO respec skipped unless the level vertex
   buffer changed. This alone was -5.0ms/frame on Geyser static.
5. 62951ac53  Bone-UBO ring upload (UBO technique): bone window uploaded once
   per flush at a ring cursor (orphan on wrap) instead of once per level at
   offset 0 over data in-flight draws still read. Trims bones-ub 15-40%
   (honest: residual ~0.7-1.0ms/bucket remains — real write cost, not sync).
Multidraw itself was evaluated and rejected: desktop glMultiDrawElements issues
one call per StripDraw — same call count as the single-draw path — so enabling
it on GLES could not reduce submissions; cross-draw merging (which desktop does
not do) strictly dominates.
