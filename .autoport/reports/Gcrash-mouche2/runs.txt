------------------------------------------------------------------------------
Forensics (MGEO geometry probe + arm64 disasm of enter-state, removed after use):
  - WRITER: `enter-state` (goal_src/jak1/kernel/gstate.gc:355-381) entering the
    buzzer `pickup` state. On arm64 the GOAL process stack lives in EE memory and
    the +8(x86) vs +16(arm64) push/.jr stack-contract asymmetry (the documented G2
    RETURN residual, goalc/compiler/CodeGenerator.cpp:585-607) leaves the buzzer's
    enter-state frame STRADDLING its 256-byte (stack-size 0x100) main-thread
    stack-top (0x1a8000): the spilled `new-state` pointer is saved ABOVE-top (e.g.
    goal:0x1a8010, in zero/DMA memory) and reads back 0. enter-state then computes
    func = (-> new-state code) + r15 with new-state(x3)=0 -> (.jr ee+0) -> SIGILL.
    Confirmed: stack-top=0x1a8000, trampoline at stack-top-16 (0x1a7ff0), x3=0,
    x12=ee+0x18aee4 (the return-from-thread-dead trampoline), the named SP-relative
    spill stomp.
  - VICTIM (cascade): Gcrash-mouche's repair caught the SIGILL but left the buzzer
    pickup state code to RETURN through a STALE X30 (arm64 .jr keeps stale RA; the
    title's suspend-looping states require that, so pop-RA cannot be a global
    codegen default — F1f tried and regressed the title). The returning state code
    re-entered enter-state's own body against the reset stack and re-dispatched in

    internal mutex -> render thread starved (blue-lock). VICTIM = the render/DMA
    delivery (A35-RENDER) starved by the wedged GOAL/kernel thread.

================================================================================
THE FIX (translation layer; goal_src 1-to-1; x86 byte-identical / unaffected)
================================================================================
1. android/gk_android_main.cpp (handle_enter_state_null_code): in the enter-state
   code==0 SIGILL repair, also set X30 = the pushed return-from-thread-dead
   trampoline (ee+0x18aee4) so the repaired pickup state code RETURNS into the
   deactivate trampoline (clean process death) instead of stale-X30 (enter-state's
   own body). Replicates F1f's pop-RA but SCOPED to this fault only (no SP shift,
   so suspend-looping states / the title are untouched). Guarded on [SP] holding
   the trampoline. arm64/Android only.
2. game/kernel/common/kprint.cpp (assert_print_buffer_has_room): on Android, when
   the GOAL print buffer overflows, RESET the buffer + rate-limit instead of
   lg::die. This breaks the runaway: the GOAL/kernel thread no longer wedges on the
   liblog mutex, keeps advancing, swap-sound-buffers drains the sound queue and the
   flood self-terminates -> render resumes. Desktop x86 keeps the strict lg::die.
