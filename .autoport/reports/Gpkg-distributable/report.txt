WHY THIS RE-RUN (the prior false-green)
--------------------------------------------------------------------------------
The first pass shipped a SLIM/incomplete bundle: it packed the on-disk staging
dirs (android/app/src/jak1/assets/{iso_data,fr3}), which had drifted to only
4 of 26 fr3 texture packs + the stale June-11 CGO/DGO code set. The APK booted
but DROPPED assets, so the main-menu orange tint backdrop rendered as a broken
narrow band with blue sky bleeding through the sides (owner screencap in
.autoport/reports/Gregress-menu-overlay/device-105736.png). The hardened
validator now gates on asset COMPLETENESS (== the full PC build) AND on in-game
RENDERING (the menu tint), not just boot/decompress/idempotency.

--------------------------------------------------------------------------------
THE FIX (packaging only — engine and goal_src untouched)
--------------------------------------------------------------------------------
android/build_asset_bundle.sh was rewritten to assemble the bundle straight from
the AUTHORITATIVE PC build outputs (not the staging dirs, which drift):
  - out/jak1/iso/            321 files: the 293 arch-independent data files
                               (STR/VAG/TXT/VIS/...) PLUS the 28 *.CGO/*.DGO.
  - out/jak1-arm64-full/iso/ the 28 ARM64-compiled CGO/DGO, built in one
                               internally-consistent pass with the same HEAD
                               goalc/libgk (no mixed-build SIGILL). These OVERLAY
                               the x86 oracle copies from out/jak1/iso.
  - out/jak1/fr3/            the FULL 26 renderer texture packs (all levels).
The bundle's iso_data/jak1 = 293 data + 28 ARM64 CGO/DGO = 321; fr3 = 26.
TOTAL = 347 files == the full PC build (file_count matches out/jak1; NOT slim).
The assembly is a symlink farm (zip dereferences symlinks -> real content), so the
full ~1.6 GiB set is packed with no multi-GiB intermediate copy, and the bundle
can never drift to a stale staging copy again. The script HARD-FAILS if the iso
count != full, if fr3 < 26 (slim-regression guard), or if KERNEL.CGO is the x86
oracle instead of the arm64 build (mixed-build guard).
Bundle version bumped 1 -> 2 so devices that ran the slim v1 re-decompress.

6. INTEGRITY + LOW-STORAGE ERROR HANDLING (LoaderActivity.java)
--------------------------------------------------------------------------------
  - Low storage: StatFs pre-check (raw_bytes * 1.05); throws a clear "Not enough
    free storage. Need …, only … free." instead of a half-unpack. DEMONSTRATED:
    "storage ok: need 1,60 GB, have 3,67 GB" on the real run.
  - Corrupt/truncated bundle: ZipInputStream.closeEntry() verifies each entry's
    CRC32 against the zip's stored value (all 347 entries validated this run).
  - Integrity cross-check: after the stream, filesWritten (347) and bytesWritten
    (1,639,349,155) are checked against manifest file_count + raw_bytes before
    the stamp is written; a short/extra/truncated archive throws. This check RAN
    and PASSED (347 == 347, bytes == manifest) this run.
  - Crash tolerance: the version stamp is written LAST, after every output file
    is closed; a kill mid-unpack leaves no stamp, so the next launch wipes the
    partial data and restarts — never boots off a half-unpack.
  - Path-traversal guard: entries whose canonical path escapes filesDir are
    refused.
