== What was built ==
1. OFFLINE BAKE (tools/grass_bake CLI + GrassBakeCore extraction, commits 53ecf68d2 + b47259fbe):
   Placement + per-instance tint/size/yaw/curvature are precomputed offline from the level fr3 into <level>.grassbake instance tables — the runtime skips the whole at-load geometry scan and hashing.
   Bake format (grass_bake::BakeData): per-triangle BakeTri = {tri geometry p0/e1/e2, deterministic seed, area, avg ground-texture color, face normal, pal[8][3], candidate count/base, flags} + per-candidate keep bitmask (floor/rim pass + occlusion) + u16 quantized rim distance.
   LIGHTING is NOT frozen at one time: pal[8][3] holds the per-triangle baked ground light at the SAME 8 time-of-day keyframes the engine bakes into the tfrag vertex color rows; the runtime interpolates the keyframes with the live itimes weights on every time-of-day change — the day-cycle lighting is baked as keyframes and interpolated exactly like the game's own tfrag ground light, then uploaded per instance (POLISH#9 path unchanged).
   Bake density 250 (slider max; runtime slider densities expand as deterministic prefixes). Training baked: out/jak1/fr3/training.grassbake.
   ASSET SIZE COST: training.grassbake = 1,659,865 bytes (1.66 MB, 22% of the 7.5 MB training.fr3). Shipped by android/build_asset_bundle.sh over the fr3 zip path (lands at files/out/jak1/fr3/) and content-hashed into the bundle VERSION so remote devices re-extract on any bake change.
   Bake validation at load: level name, fr3 byte size, floor-gap, bake-density >= slider — any mismatch logs "[recharged-grass] PRECOMPUTED unavailable (<reason>)" and falls back to LIVE.
2. GRASS MODE toggle (commit a05515f5f): "PRECOMPUTED GRASS" ON/OFF row in the GRASS SETTINGS nested submenu (progress-pc.gc); ON = PRECOMPUTED (baked day-cycle tables) / OFF = LIVE (full at-load scan).
   Persisted as (recharged-grass-precomputed? #t/#f) in pc-settings.gc (pckernel read+write), pushed to the renderer per frame via the pc-set-grass-dists! w channel; default #t (precomputed preferred; un-baked levels auto-fall back to LIVE). Grass OFF still == stock render.
3. LIVE path is the identical GrassBakeCore scan->tables->expand pipeline run at load (behavior-preserving C1 extraction, -ffp-contract=off pinned), so both modes share expand() and the keyframe-interpolation lighting — by construction the same fidelity.

== BLOCKER found + fixed: arm64 bug class #14 (commit 958a4eda6) ==
Attempt-1's A/B was void: ALL rounds ran precomputed because the pc-settings file NEVER loaded on Android ("could not be loaded, using defaults" — true of every boot since the poc era; unnoticed because owner values were made defaults). Root cause (proven by x86-parses-fine + device file-bisect + an inert kread recompile flipping the failure): the GOAL->C++ FFI trampolines did not save the GOAL callee-saved GPR bank {RBX,RBP,R10,R11,R12} = arm64 {X3,X5,X10,X11,X12} (identity id->Xn map; AAPCS lets C++ clobber all five, x86 saves exactly this set via _arg_call_systemv + SysV). kread() clobbered a live bank register in the settings parser -> dosettings desynced at one case branch. Fixed in make_function_from_c_arm64 + make_stack_arg_function_from_c_arm64 (jak1+jak2, which also never had the A40 q24-31 save) and _arg_call/_stack_call/_mips2c_call_arm64. Side win: pc-settings persistence now works on Android for the first time. Diagnostic kept: prop/env-gated kread/kseek trace (debug.opengoal.kio_trace / OG_KIO_TRACE).
