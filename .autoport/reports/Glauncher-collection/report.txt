================================================================================
THE MODEL (owner 2026-06-30, REVISED) — how the APK behaves is ASSET-DRIVEN
================================================================================
The set of games in an APK == which per-game asset bundles (`<game>_assets.zip`)
are present under that flavor's assets/bundle/ dir AT BUILD TIME.
  - EXACTLY ONE game  -> SINGLE-GAME build: NO launcher menu; the APK boots
                         STRAIGHT into that game, with that game's own launcher
                         name + icon.
  - MORE THAN ONE     -> COLLECTION build: launcher label
                         "Jak and Daxter: The Recharged Jak-pot" + a boot
                         SELECTION MENU (text rows, usable by TOUCH and by
                         GAMEPAD/D-pad); pick one -> unpack it -> launch it.
The same detection runs at BUILD time (Gradle, sets the label/icon) and at
RUNTIME (LoaderActivity enumerates the bundled archives), so dropping a 2nd
game's bundle into a flavor flips it to collection with no other code change.

3. ASSET-DRIVEN 1-vs-COLLECTION DETECTION (build-time + runtime + dry-run)
================================================================================
BUILD-TIME (build.gradle.kts detectBundledGames + `printGameDetection` task —
scans each flavor's assets/bundle/ for `<game>_assets.zip`):
  DETECT flavor=jak1  bundledGames=[jak1] count=1 mode=SINGLE      label="Jak & Daxter"
  DETECT flavor=jak2  bundledGames=[]     count=0 mode=SINGLE      label="Jak II"
  DETECT flavor=jak3  bundledGames=[]     count=0 mode=SINGLE      label="Jak 3"
  DETECT flavor=collection bundledGames=[] count=0 mode=COLLECTION(empty) label="Jak and Daxter: The Recharged Jak-pot"
DRY-RUN (no real 2nd game needed) — stage a synthetic 2-zip dir and detect:
  `./gradlew printGameDetection -PdetectDir=<dir with jak1_assets.zip + jak2_assets.zip>`
  DETECT dir=… games=[jak1, jak2] count=2 mode=COLLECTION label="Jak and Daxter: The Recharged Jak-pot"
  `-PdetectDir=<dir with only jak3_assets.zip>`
  DETECT dir=… games=[jak3] count=1 mode=SINGLE label="Jak 3"
RUNTIME (LoaderActivity.installedGames()): enumerates assets/bundle/*_assets.zip;
1 -> direct boot, >1 -> menu. A per-game manifest (bundle/<game>.manifest.properties,
now also emitted by build_asset_bundle.sh) lets multiple games' bundles coexist;
the loader falls back to the legacy bundle/manifest.properties for the single
jak1 bundle, and jak1 keeps its historical version-stamp name so an existing
jak1 install is NOT forced to re-decompress on upgrade.
