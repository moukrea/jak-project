f30-0 / xmm8-15 / spool PRESERVATION (the corruption this fix kills)
--------------------------------------------------------------------------------
The f30-0 class is the GOAL-float-across-FFI corruption: the spooled-anim frame-rate
scale f30-0 (loader.gc::ja-play-spooled-anim) is held in goalc xmm8-15 = arm64 V24-V31
across the per-frame spool loop; a C++/mips2c callee (AAPCS caller-saves V16-V31) clobbered
that bank, collapsing f30-0 -> the title-spool anim rate + the Gd1/Gcine cutscene "slow-mo"
/ discrete-cut collapse.

Preservation is established on THREE independent legs (full detail in
.autoport/reports/Gffi-xmm-validate-fix-summary.md):

 1. DEDUCTIVE (proven against goalc): XMM0..XMM15 = register ids 16..31 (emitter/Register.h);
    AArch64 V-reg = arm64_reg5(r)=r.id()&0x1f, no remap (emitter/IGenARM64.cpp) => xmm8->V24,
    xmm15->V31. XMM8-15 saved=true (emitter/Register.cpp m_saved_xmms); calls clobber only
    temp() regs (compiler/IR.cpp) so live floats stay in V24-V31 UNSPILLED across the call.
    AAPCS clobbers V16-V31 -> saving V24-V31 is exactly necessary. So a GOAL float in
    xmm8-15 is PRESERVED across a GOAL->C++ FFI call iff the trampoline saves q24-q31 — which
    it now does. x86 unaffected (same gRegInfo; SysV caller-saves all xmm) -> our-x86==orig-x86.

 2. ROUTING: f30-0's spool loop crosses into C++ ONLY via the joint-anim mips2c path
    (ja-no-eval :frame-num / seek! -> joint.cpp), which returns through _mips2c_call_arm64 —
    the trampoline that carries the q24-q31 fix. The loop's other leaf calls (current-str-pos,
    current-time, current-str-id, str-play-async, execute-commands-up-to, spool-push) are pure
    GOAL (no FFI). So the fix is SUFFICIENT to kill the f30-0 class at the source.

 3. EMPIRICAL: in this soak the f30-0-sensitive paths ran crash-free at full rate — the
    ndi-intro streamed cinematic AND the injected NEW-GAME intro cinematic both completed and
    handed off to gameplay (engine: state=in-game, master-mode=game), and the run sustained to
    frame 10620 with 0 sig(4/6/11)/Fatal. The mips2c-routed spool/cutscene did not corrupt.

    Established device calibration (Gfix-title-rays, this exact fix): swapping the saved SIMD
