## Forensics — faulting fn/PC named, writer named by mprotect watch
- The faulting instruction at string=+0x13c is `LDRB W1,[X16]` with X16 = EE_base(0x7f00000000) + GOAL
  0xa8c12fe6 (x8=0xa8c12fee): string= dereferenced a GARBAGE name pointer 0xa8c12fe6 (far beyond the
  128 MB EE, NOT a valid string). Caller lookup-part-group-pointer-by-name iterates *part-group-id-table*
  and calls (string= arg0 (-> group name)); the slot's sparticle-launch-group object is at a VALID
  swamp-heap address but its `name` field (offset 12) is garbage. Crash SP only ~1136 bytes deep => NOT
  a stack overflow.
- 0xa8c12fe6 is a 2-bit-perturbed copy of goalc's arm64 BLR-restore word 0xA8C12FEA (`ldp x10,x11,[sp],#16`)
  -> the name field was overwritten with ARM64 CODE. A per-dispatch content canary (SWAMP-HEAL) showed
  NINE consecutive part-group slots (107-115) whose name fields became different arm64 instruction words
  (a8c117e3 ldp, aa0e03e0 mov, 910043ff add sp, f9400209 ldr, d2800007 movz, 90000009 adrp ...) —
  a contiguous code overwrite of live launch-group static data. Deterministic, byte-identical every run.
- An mprotect write-watch (A38 tripwire, band 0x2dfc000..0x2e01000) NAMED THE WRITER: libc memcpy
  (STP 16-byte chunks of arm64 code) called from lr = _ZN12link_control12jak1_work_v3Ev+0x194
  (game/kernel/jak1/klink.cpp) — i.e. the runtime linker copying a re-linked object segment.

## Classification (arm64-only; x86 golden runs the identical route crash-free)
LEVEL-HEAP-REUSE RACE, arm64 codegen-size-driven. Jak1 has only 2 level heaps (LEVEL_COUNT=2, heap A =
[0x2df0000,0x381c000)); the pontoon route thrashes 3 levels (village2+rolling+swamp) through them
("Adding level swamp ... rolling ... swamp"). link_control::jak1_work_v3 (klink.cpp:305/321/337)
ultimate_memcpy's each object segment into a kmalloc'd level-heap destination. On arm64 the object
segments are BULKIER (top-level link block 3860 vs 2634 bytes), so a level's login/link spans MORE
frames and STRADDLES a discard: rolling's unload runs unlink-part-group-by-heap (clears its slots), then
an in-flight racer-part (ROL.DGO, ids 108-115) link FINISHES and RE-registers those slots into heap A
just as swamp reuses heap A — jak1_work_v3's memcpy then copies swamp/rolling code over those live
launch-group objects; *part-group-id-table* still points at them, and string= derefs the code word. On
x86 the link completes inside the discard frame, so the registration and the heap reuse never interleave.
NOT the corrupt-LDP bare-RET class Gcrash-rockvillage handled (that is pc==lr, fault==pc; this is a DATA
deref, fault != pc), NOT mips2c, NOT stack, NOT a DMA race (deterministic).

## Why Gcrash-rockvillage's fix MISSED it (and why it was a false-green)
Its handle_bare_ret_offset repairs only the pc==lr && fault==pc bare-RET sink (a corrupted return slot);
this swamp crash is a data-load fault (fault != pc), a different sink, so that handler correctly never
fires. Its validation used a want-levels replay that LINKED SWA.DGO but never DISPLAYED the swamp with
Jak present, so the swamp part-spawner init (which runs the lookup) never executed and the crash never
surfaced. The reopen's HARD real-route rule exposed it.

## FIX (1-to-1, translation layer only; game/kernel/jak1/klink.cpp + kmachine.cpp, arm64/Android-gated)
invalidate_part_groups_in_range(dst_goal, size) (kmachine.cpp): before each level-heap segment
ultimate_memcpy in jak1_work_v3 (klink.cpp, immediately before the MAIN and TOP-LEVEL copies, guarded to
level heaps only: m_heap != kglobalheap && m_heap != kdebugheap), clear every *part-group-id-table* slot
whose sparticle-launch-group pointer lies in [dst, dst+size) — the exact range about to be overwritten.
This is the C++ emulation of the game's own unlink-part-group-by-heap, keyed on the ACTUAL write range,
so it cannot lose the async-link/discard race regardless of interleaving. The new segment's top-level
re-registers valid groups afterward; the lookup tests (and (nonzero? v1-2) ...) so a 0 slot is safely
skipped. Race-free (runs synchronously on the same thread right before the memcpy). Gated
#if defined(__ANDROID__); x86 build byte-identical (verified: build-x86 gk built clean, all new code
Android-only). goal_src (non-pc) untouched; goalc/emitter/IGenX86_64 untouched; .autoport/gold untouched.
The failed per-dispatch poll-heal attempt (swamp_partgroup_heal_maybe) was REMOVED — it raced (heal ran
before the same-tick corruption) and healed only the name word of a fully-code-overwritten object.
