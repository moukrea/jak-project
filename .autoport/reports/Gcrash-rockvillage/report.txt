## Forensics — faulting fn/PC named, mechanism bracketed live
- pc==lr==0x1d7b30 is a BARE GOAL offset (missing the 0x7f00000000 EE base): a GOAL
  state-function RET consumed a corrupted saved-X30 slot and fetch-faulted at the
  unmapped low address (fault==pc). 0x1d7b30 = *camera-combiner*(0x1d7ac4)+0x6c — i.e.
  camera-object-interior DATA, not code.
- enter-state (gstate.gc:355-386) resets SP to the process stack-top and pushes the
  host return-from-thread-dead trampoline; the state fn's STP saves it at [top-24].
- GRV-CANARY (per-dispatch watch of that band) caught the corruption LIVE, repeatedly,
  in every scenario run: [top-24] holds host return-from-thread-dead (0x7f0018aef4) and
  then takes per-frame FLOAT writes — camera-blend/direction-class values in [-1,1]
  (0x3f79xxxx…0xbf65xxxx, converging seeker shapes = cam-float-seeker::update!
  signature, camera-h.gc:181-192; village2 water + warp-gate triggers) — landed through
  the SHARED *kernel-dram-stack* arena (gkernel.gc:108-116; target + post threads +
  process-tree main all run there, gkernel.gc:1389,1972, logic-target.gc:1279).
- Discriminator (canary v5): across 23 corruption episodes, the intruding float value
  has ZERO twins inside the camera process objects — the arena slot is the value's ONLY
  home. So the writes are another thread's legitimate frame/spill traffic on the SHARED
  arena (serialized by suspend-backup/restore; normally healed), NOT a duplicated heap
  write. On x86's 8-byte push contract the same traffic lands on a slot that is dead by
  the time it is consumed — benign; on arm64 (16-byte push + STP frame) it collides
  with the LIVE saved-X30 of the outermost state frame, fatal when consumed unhealed.
- x86 layout mapping (uniform delta +0x74e0) confirms the crash SP (0x1a7ed0) sits in
  static engine data past the arena — consistent with consuming arena-scribbled state.
  This is the arm64-only divergence; the game source is byte-identical to original.

## Classification
arm64 stack/return-slot stomp (shared dram-arena scribble consumed at state return) —
the corrupt-LDP-then-RET class (A23/A24 lineage), camera-float writer family. NOT
DGO-streaming (ruled out: full SWA mid-play stream crash-free, repro10 + zone sweep),
NOT "enough stack" (no such abort), NOT a renderer/GL stomp (EE-thread RET fault),
NOT mips2c sparticle #f-guard at this site (survey found those sites guarded; the
float shape is camera seeker class).

## FIX (1-to-1, translation layer only; android/gk_android_main.cpp, commit 044d7ae10)
handle_bare_ret_offset — repair-and-resume inside the fault handler (the established
arm64 stomp pattern: Gcine-crash3, Gmatch rftd handlers in the same file):
  gate:   SIGSEGV && pc==lr && pc in [0x1000, EE_SIZE) && fault==pc  (razor-tight:
          only a RET/BR through a corrupted GOAL-value slot fetch-faults there)
  repair: pc := EE_base + (symbol-value return-from-thread-dead)  [live-resolved, not
          hardcoded] — the deactivate trampoline, exactly the continuation the x86
          contract reaches for a returning state :code; counter GRV-BARE-RET-REPAIR.
goal_src (non-pc) untouched; goalc/emitter/IGenX86_64 untouched; .autoport/gold
untouched; x86 build byte-identical behavior (fix is Android-runtime only).
