# OpenGOAL — Android port

This directory is the Android packaging layer for the OpenGOAL runtime
(autoport phases 10, 12, and 13). The native code lives in `libgk.so`,
built by the top-level CMake project under `build-android/`. This Gradle
project wraps that `.so` plus a thin Java activity into a per-game APK.

## Per-game APK variants

The desktop runtime is a single binary that selects a game at launch
(`gk --game jak1`). Android mirrors that with **product flavors** —
`jak1`, `jak2`, `jak3` — built from one source tree. Each produces a
separately installable APK:

| Flavor | applicationId        | versionName suffix | App label          |
|--------|----------------------|--------------------|--------------------|
| jak1   | org.opengoal.gk.jak1 | -jak1              | OpenGOAL — Jak 1   |
| jak2   | org.opengoal.gk.jak2 | -jak2              | OpenGOAL — Jak 2   |
| jak3   | org.opengoal.gk.jak3 | -jak3              | OpenGOAL — Jak 3   |

Each flavor's game name is exposed to Java as the `R.string.game_name`
resource (set via `resValue()` in `app/build.gradle.kts`), so
`MainActivity` passes it into `NativeGk.startGame(name, dataRoot)`
without baking the selection into native code.

Per-flavor source sets live at:

```
android/app/src/jak1/   # assets/, java/, AndroidManifest.xml overlay
android/app/src/jak2/
android/app/src/jak3/
```

The `assets/iso_data/<game>/` subdirectory under each flavor is the
landing zone for the extracted PS2 disc contents that phases 14-16
populate (one game per APK variant).

## Game data path

The runtime needs the player's own PS2 ISO extract; we don't ship game
data. Phase 13 lays the plumbing for both options below — pick the
simpler one depending on data size:

- **First-launch copy.** On first boot, `MainActivity` copies
  `assets/iso_data/<game>/` from the APK into
  `getFilesDir()/iso_data/<game>/` and points the runtime at the
  filesystem path. Simple; doubles on-disk size; works with stock
  fopen-based I/O.
- **AAssetManager mapping.** Use `AAssetManager_open` +
  `AAsset_openFileDescriptor` to feed the runtime a `(fd, offset,
  length)` view directly into the APK zip. No unpacking; requires the
  runtime to handle non-seekable / pread-style access.

Phase 13 itself doesn't ship game data — that's phases 14-16. The
activity Toasts a "Missing data" hint if the target dir is empty.

## Building (developer environment)

Requires JDK 17+, Android SDK 34, Android NDK r27c.

```
# 1. Build libgk.so via NDK (phase 10/12)
cmake -S . -B build-android -GNinja \
      -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK_HOME/build/cmake/android.toolchain.cmake \
      -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-29 \
      -DANDROID=1
cmake --build build-android --target gk

# 2. Build one flavor's APK (phase 13)
cd android
./gradlew assembleJak1Debug        # produces app/build/outputs/apk/jak1/debug/app-jak1-debug.apk
./gradlew assembleJak2Debug
./gradlew assembleJak3Debug

# Or all flavors at once:
./gradlew assembleDebug
```

`copyNativeLibs` picks up `build-android/lib/arm64-v8a/libgk.so` and
stages it into `app/src/main/jniLibs/arm64-v8a/` so AGP packages it
into the APK.

## Installing & running on an emulator

```
adb install -r app/build/outputs/apk/jak1/debug/app-jak1-debug.apk
adb logcat -c
adb shell am start -n org.opengoal.gk.jak1/org.opengoal.gk.MainActivity
adb logcat -d | grep "target started"
```

A `target started: <version>` line in logcat is the boot success signal
(same as phase 11).

## Game data (user-supplied)

OpenGOAL needs the player's own copy of the PS2 ISO data — it is not
shipped with the APK. The activity expects it under app-private
internal storage:

```
/data/data/org.opengoal.gk.jak1/files/iso_data/jak1/
/data/data/org.opengoal.gk.jak2/files/iso_data/jak2/
/data/data/org.opengoal.gk.jak3/files/iso_data/jak3/
```

The activity Toasts a hint to the player if the target subdirectory for
its flavor is empty. Phases 14-16 will fold the data into the APK as
assets so the user doesn't have to side-load.

## APK size and asset packs

If a per-flavor APK ever crosses 150 MB at assembly time (likely in
phases 14-16 when game data lands), switch the build to
`./gradlew bundleJakNDebug` to produce an Android App Bundle (`.aab`)
with the game data carved into asset packs.
